Windows 上 Tauri 还需要 **WebView2 运行时**（Win11 自带）和 **MSVC 构建工具**。

## Windows：先用 dev.ps1

DeepSeek Harness Desktop 把自己的命令 shim 装到 `%LOCALAPPDATA%deepseek-harnessin` 并排在
npm 全局 bin **前面**，它的 `pnpm.cmd` 在托管版装好前会拒绝执行 —— 所以在 PowerShell 里直接
`pnpm tauri dev` 会死在 `[pnpm] pnpm not found`。

```powershell
.scriptsdev.ps1                      # 用 .dev-home/provider.env 里的密钥
.scriptsdev.ps1 -ApiKey oc_sk_...    # 这次运行临时指定
.scriptsdev.ps1 -Command build       # 生产构建
```

脚本只改**自己进程**的 PATH，不动机器级配置。

## 命令

```bash
pnpm install                 # JS 依赖
pnpm kernel:fetch            # 拉内核到 kernel/（git-ignored）
pnpm tauri dev               # 开发模式，Vite + Tauri 热重载
pnpm build                   # 前端生产构建
cargo check --workspace      # Rust 类型检查
cargo test --workspace       # Rust 测试
cargo clippy --workspace -- -D warnings
```

`cargo check` 首次会编译整个 Tauri 依赖树，约 5 分钟；之后增量秒级。

## 内核拉取

内核不进仓库。`profiles/sdk/kernel.json` 钉住精确版本，`scripts/fetch-kernel.mjs`：

1. 读 `kernel.json` 的 `version`；
2. 用 pnpm 把 `@deepseek-ai/dsh@<version>` 装到 `.kernel-staging/`；
3. 校验解出的 `package.json` 版本一致；
4. 原子改名成 `kernel/`；失败时旧内核原样保留。

升级内核 = 改 `kernel.json` 一行 + 重跑。

### 体积：819 MB，这是待解决的问题

`@deepseek-ai/dsh` 是**覆盖全部 profile 的元包**，有 91 个直接依赖 —— 连 Web 前端、
桌面 UI 包、LibreOffice 工具链、语音识别都一起装了，哪怕 `sdk` profile 一行都不加载它们。

实测大头（`du -sh kernel/node_modules/.pnpm/*`）：

| 包 | 体积 |
| --- | --- |
| `@deepseek-ai/libreoffice-kit-win32-x64` | 191 MB |
| `@deepseek-ai/libreoffice-kit-wasm` | 146 MB |
| `@deepseek-ai/dsh-experimental-*` | 28 MB |
| `openai` | 26 MB |
| `node-pty` | 26 MB |
| `@deepseek-ai/dsh-client-ui-*` | 24 MB |
| `sherpa-onnx-win-x64` | 23 MB |
| `@deepseek-ai/dsh-web-frontend` | 21 MB |
| `img-sharp-win32-x64` | 19 MB |

剪枝在 M6 做，顺序不能反：**先在 profile patch 里 `disabled: true` 掉引用它们的行**（`office-kit`、
`tool-office`、`skill-office`、`tool-web` 等），确认内核启动正常，再删目录。反过来做会得到一个
启动即崩的内核。

## 验证

```bash
pnpm kernel:smoke           # 拉起内核、发 initialize、断言回包、发 shutdown
```

这是 M0 的验收入口：不需要 API key（不发模型请求），30 秒内必须打出
`serverInfo: {"name":"deepseek-harness-sdk-runtime",...}` 并以 0 退出。


## 打包

```bash
pnpm tauri build            # 当前平台
```

产物进 `target/release/bundle/`。内核运行时（Node + `kernel/`）作为 resources 一起打进去，
安装包预计 150~250 MB —— Node 那部分是省不掉的，Tauri 省的只是 Chromium。

## 禁区

- `node_modules/`、`target/`、`dist/`、`kernel/`、`dsh-home/`：生成物与运行时
- `.env*`、`*.key`、`*.pem`、`.credentials.yaml`：密钥
- `deepseek-harness/`：本机只读的上游源码，不属于本项目

## 已知的坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 内核输出解析失败 | stdout 混进了日志 | 日志走 stderr，两路分开接 |
| 会话列表为空 | `DSH_HOME` 指错 | 用应用私有目录，别用 `~/.dsh` |
| 首次 `cargo check` 极慢 | 编译 Tauri 依赖树 | 正常，之后增量 |
| `pnpm` 命令不存在 | corepack 在本机坏了 | `npm i -g pnpm` |
| `ERR_PNPM_IGNORED_BUILDS` | pnpm 12 默认拦 postinstall | `pnpm approve-builds --all`，或靠 `pnpm-workspace.yaml` 的 `onlyBuiltDependencies` |
| `icons/icon.ico not found` | 图标没生成 | `pnpm icons` |
