## 启动开发环境：用 dev.mjs

DeepSeek Harness Desktop 把自己的命令 shim 装到 `%LOCALAPPDATA%\deepseek-harness\bin` 并排在
npm 全局 bin **前面**，它的 `pnpm.cmd` 在托管版装好前会拒绝执行 —— 所以直接
`pnpm tauri dev` 会死在 `[pnpm] pnpm not found`。

```powershell
node scripts/dev.mjs                     # 用 .dev-home/provider.env 里的密钥
node scripts/dev.mjs build               # 生产构建
node scripts/dev.mjs --check             # 只打印解析出的环境，不启动
```

脚本只改**自己进程**的 PATH，不动机器级配置。

## 命令

```bash
pnpm install                 # JS 依赖
pnpm kernel:fetch            # 拉内核到 kernel/（git-ignored）
pnpm tauri dev               # 开发模式，Vite + Tauri 热重载
pnpm build                   # 前端生产构建
cargo check --workspace      # Rust 类型检查
cargo test --workspace       # Rust 测试
cargo clippy --workspace -- -D warnings
```

`cargo check` 首次会编译整个 Tauri 依赖树，约 5 分钟；之后增量秒级。

## 内核拉取

内核不进仓库。`profiles/sdk/kernel.json` 钉住精确版本，`scripts/fetch-kernel.mjs`：

1. 读 `kernel.json` 的 `version`；
2. 用 pnpm 把 `@deepseek-ai/dsh@<version>` 装到 `.kernel-staging/`；
3. 校验解出的 `package.json` 版本一致；
4. 原子改名成 `kernel/`；失败时旧内核原样保留。

升级内核 = 改 `kernel.json` 一行 + 重跑。

### 体积：819 MB，这是待解决的问题

`@deepseek-ai/dsh` 是**覆盖全部 profile 的元包**，有 91 个直接依赖 —— 连 Web 前端、
桌面 UI 包、LibreOffice 工具链、语音识别都一起装了，哪怕 `sdk` profile 一行都不加载它们。

实测大头（`du -sh kernel/node_modules/.pnpm/*`）：

| 包 | 体积 |
| --- | --- |
| `@deepseek-ai/libreoffice-kit-win32-x64` | 191 MB |
| `@deepseek-ai/libreoffice-kit-wasm` | 146 MB |
| `@deepseek-ai/dsh-experimental-*` | 28 MB |
| `openai` | 26 MB |
| `node-pty` | 26 MB |
| `@deepseek-ai/dsh-client-ui-*` | 24 MB |
| `sherpa-onnx-win-x64` | 23 MB |
| `@deepseek-ai/dsh-web-frontend` | 21 MB |
| `img-sharp-win32-x64` | 19 MB |

剪枝在 M6 做，顺序不能反：**先在 profile patch 里 `disabled: true` 掉引用它们的行**（`office-kit`、
`tool-office`、`skill-office`、`tool-web` 等），确认内核启动正常，再删目录。反过来做会得到一个
启动即崩的内核。

## 内核瘦身

`kernel/` 拉下来 753 MB。`pnpm kernel:slim` 报出可剪的候选和各自的理由；`--apply` 才动手。

**每剪一组都要跑一次真内核。** 不是握手，是「初始化 + 发一句要调工具的话 + 要求 turn 完成」——
profile 里大部分行是懒加载的，一个缺失的包最先炸的是工具调用，不是启动。

```
[slim] moved aside 1 cop(ies), 190 MB
[slim]   verified — the kernel still completes a turn with a tool call
...
[slim] pruned 66 package(s), restored 0
```

剪掉的（都是 SDK profile 用不到的）：

| 包 | 体积 | 为什么不要 |
| --- | --- | --- |
| `libreoffice-kit-win32-x64` | 190 MB | 桌面客户端没有挂 Office 工具 |
| `libreoffice-kit-wasm` | 145 MB | 同一套 kit 的 WASM 版 |
| `sherpa-onnx-win-x64` | 22 MB | 语音输入，本客户端不提供 |
| `dsh-web-frontend` | 20 MB | 上游 Web GUI 打包，我们自带前端 |
| `dsh-client-ui-*`（62 份） | 63 MB | 同上，pnpm 按 peer 组合存了 62 份 |

结果：**753 MB → 370 MB**（`du`，含块对齐）；脚本按文件大小算 312 MB。

回滚：`pnpm kernel:fetch`。不要留手动搬走的副本——留着的成本正好等于剪掉的收益，而
`fetch` 是从钉死版本重建，比信任一个被人手动移动过的目录可靠。

验证门禁自己也有过一个 bug，值得记：一开始它在 `session/prompt` **被接受**时就判定完成并杀
进程，于是每组都"失败"。`session/prompt` 立即返回 message id，turn 是之后才跑的——要等
`turn/end`。症状（"没有完成的 turn"）看起来像被剪的包有问题，其实完全不是。


## 日志

`tracing` 同时写 stderr 与文件：`<dsh_home>/logs/desktop.log.YYYY-MM-DD`（rolling appender
会在名字后加日期，精确匹配 `desktop.log` 永远找不到文件）。

**同步写，不用 non-blocking。** non-blocking 更快，但进程被强杀时缓冲区全丢——而"进程被强杀"
恰恰是日志存在的理由。

没有日志目录时不阻止启动：打印一行到 stderr 继续跑。

## 打包

```bash
cargo build --release -p dsh-desktop-app   # 客户端
pnpm bundle:apply                          # 组装 dist-bundle/：客户端 + 内核 + node
```

为什么不是「5 MB 安装包」：客户端离了内核没用，内核是 370 MB 的 JavaScript，JavaScript 需要
Node。所以要么一次性给全（本脚本的做法：客户端 + 内核 + Node 运行时）要么首次启动下载 500 MB。
我们选前者——**首次启动不依赖网络，也不要求系统里装了 Node**。

`state.rs` 从可执行文件所在目录解析 `kernel/` 与 `node`，所以 dist-bundle 是自包含的。

**还没做**：安装器签名、自动更新、`tauri build` 真正出包（配置在，未跑过）。

## CI

`.github/workflows/ci.yml` 三个 job：

| job | 做什么 |
| --- | --- |
| `web` | tsc + vitest + vite build（`--ignore-scripts`，不需要原生依赖） |
| `rust` | fmt + clippy `-D warnings` + 全量测试（不拉内核，相关测试自动跳过） |
| `smoke` | 拉内核 → 瘦身 → 构建 → 跑真客户端断言三件事 |

`smoke` 是唯一需要网络的 job，也是唯一能挡住"前端没加载""内核没握手"这两类事故的。

## 无头 E2E

```bash
pnpm smoke:app              # 用 target/release 的二进制
node scripts/smoke-app.mjs --binary <path>
```

带 `DSH_DESKTOP_AUTOSTART=1` 启动真客户端，从**日志文件**里断言三件事：

1. `kernel_paths invoked` —— 内嵌前端加载了、IPC 通了
2. `kernel_initialize ok` —— 内核起来了、握手完成
3. `session_list count=N` —— 会话存储读到了

不点鼠标：窗口里的点击需要注入键盘，CI 里做不到，而上述三件事恰好覆盖了历史上真出过的事故
（空白窗口、内核没起来）。

## 构建缓存被外部进程锁住

这台机器上 `ComfyUI` 的 python 进程会持有 `target/release/build/...` 里的构建脚本产物，导致
`LNK1104`。绕开方式：换一个 target 目录

```bash
CARGO_TARGET_DIR=D:/dsh-build-target cargo build --release -p dsh-desktop-app
```

`scripts/handles.mjs <path>` 能点名任何锁住文件的进程（`--kill` 直接杀）。这个工具不是玩具：
它先后抓到过 `tailscale-ipn`、`clash-verge-service`、`wallpaper64`、`MIXLINE` 和这里的 python。

## 一条命令验完（pnpm verify）

```bash
pnpm verify            # 8 项，约 2~3 分钟
pnpm verify --fast     # 跳过 build 与 smoke
pnpm verify --only=rust
```

| 组 | 检查 | 它抓到过什么 |
| --- | --- | --- |
| rust | rustfmt / clippy / cargo test | **Linux 专属的未用导入**（本地编译不出，只能被 `-D warnings` 判死） |
| kernel | 三条真内核往返（分叉、图片块、重启） | header 少 `type`、多余 `null` 字段、`session/prompt` 的创建语义 |
| front | 类型检查 / 测试 / 生产构建 | 测试依赖墙上时钟、ci 上没有 `dist/` 导致 Tauri 宏 panic |
| smoke | 无头跑真二进制 | release 包没内嵌前端（窗口全白、stdout 全空） |

设计上有三条是刻意的：

1. **跳过要打印**：`0 passed · 0 failed · 3 skipped` 会列出每个 skip 的原因。因为没跑而通过的
   检查比没有检查更糟。
2. **失败给可复现命令**：每组失败都打出完整命令行与输出末 15 行。
3. **中文不乱码**：Windows 控制台默认代码页会让孩子进程的中文报错变乱码，所以每次运行先
   `chcp 65001`——报错读不懂等于没有报错。

## 验证内核行为

有三件事**不能靠读文档确认**，只能问内核：

| 问题 | 测试 | 结论来源 |
| --- | --- | --- |
| 分叉出来的会话内核认不认 | `crates/dsh-runtime/tests/fork_resume.rs` | 内核 resume 成功 |
| 图片块形状对不对 | `crates/dsh-runtime/tests/prompt_blocks.rs` | 内核返回 `messageId` |
| 内核死了池能不能重来 | `crates/dsh-runtime/tests/restart.rs` | 同路由第二个进程起来 |

三条都按 `DSH_DESKTOP_HOME` / `DSH_DESKTOP_KERNEL` 是否设置来跳过，所以 `cargo test` 在没有
内核的机器上仍然是绿的。跑全量的方式：

```bash
DSH_DESKTOP_HOME=.dev-home DSH_DESKTOP_KERNEL=kernel \
  cargo test -p dsh-runtime --release --test fork_resume --test prompt_blocks --test restart
```

**写这些测试踩过的坑值得记住**：`session/prompt` 是**创建**语义（已存在就报
`already exists`），所以验证图片块时用全新 id 比"分叉一个再发"简单，也不会碰用户的会话。

## 仓库卫生

审计过的现状（2026-11-16，命令都在下面）：

| 项 | 结果 |
| --- | --- |
| 跟踪文件数 | 125 |
| 最大文件 | `pnpm-lock.yaml` 141 KB、`Cargo.lock` 132 KB —— 都是 lock 文件，该在 |
| 密钥 | 无（`sk-`/`ghp_`/`AKIA`/私钥头/`.env`/`provider.env` 全部零命中） |
| 行尾 | 116 个 LF、0 个 CRLF |
| 分支 | 只有 `main`，没有遗留分支或 worktree |

### 每条怎么自己查

```bash
# 最大的跟踪文件
git ls-files -z | xargs -0 -I{} sh -c 'printf "%s %s\n" "$(wc -c < "{}")" "{}"' | sort -rn | head -10

# 密钥（排除 lock）
git grep -nIE "(sk-[a-zA-Z0-9]{16,}|ghp_[a-zA-Z0-9]{20,}|AKIA[0-9A-Z]{16}|-----BEGIN [A-Z ]*PRIVATE KEY-----)" -- . ':!*.lock'

# 行尾
git ls-files --eol | grep -c crlf     # 期望 0
```

### 为什么要 `.gitattributes`

这个仓库在 Windows 上开发、在 Linux 上被 CI 检查。没有它，一个 `core.autocrlf=true` 的克隆
会把每个文本文件改成 CRLF，然后第一次 `cargo fmt --check` 报「整棵树都变了」——一个和代码
毫无关系的 diff。现在 `* text=auto eol=lf` 把这件事定死；lock 文件和 `ipc.ts`（生成物）标成
`-diff`，避免有人手改它们。

### 为什么要 `.editorconfig`

同一个原因的另一半：**编辑器默认值和 rustfmt 打架时，diff 里全是空白**。文件里写清了缩进、
行尾、末尾换行；Markdown 例外——行尾两个空格是硬换行，不能删。

### 临时脚本

根目录偶尔会出现 `.u1.mjs` 这类一次性探查脚本（改文件、跑一次、删掉）。`.gitignore` 里加了
`/.[a-z][0-9]*.mjs` 兜底：忘记删也不会进版本库。
