# 句柄占用：怎么查、怎么破

Windows 上「文件被占用」的报错**从来不会告诉你是谁**：删除目录报「拒绝访问」、写文件报
「另一个进程正在使用」、WebView2 报 `0x800700AA`（资源在使用中）或 `0x8000FFFF`
（灾难性故障）。三种措辞、同一个原因。

本仓库为此带了一个工具，不依赖 Sysinternals，不需要管理员权限：

```powershell
node scripts/handles.mjs <路径>                       # 谁占着
node scripts/handles.mjs <路径> --kill                # 杀掉
node scripts/handles.mjs <路径> --kill --only tailscale-ipn   # 只杀某类进程
```

它用的是 **Restart Manager**（Windows 自己那套「文件正在被使用，请关闭以下应用」的机制），
所以给出的是系统自己的答案，不是启发式猜测。

## 本机已知的肇事者

2026-11-15 实测：**`tailscale-ipn`（Tailscale GUI 客户端）**会锁住本仓库
`target/debug/dsh-desktop-app.exe`，导致重新构建后无法启动，报
「The process cannot access the file because it is being used by another process」。
同一个进程也被怀疑是 WebView2 建环境失败的来源。

```powershell
node scripts/handles.mjs "D:\deepseek harness desktop\target\debug\dsh-desktop-app.exe"
# [handles] 1 process(es) hold ...exe
#   pid 21148  tailscale-ipn  Tailscale GUI client
```

## 遇到时的处理顺序

1. **先确认是不是它**：跑上面的命令。**不要**直接删目录或改权限——那是把占用误判成
   权限问题，越修越乱。
2. **能杀就杀**：`--kill --only tailscale-ipn`。Tailscale 的服务会自动拉起 GUI，VPN 连接
   通常不受影响。
3. **杀不掉再绕**：把 exe 复制到别的目录跑（`%TEMP%\dsh-run-test\`），先验证程序本身没问题。
   这一步也用来区分「代码坏了」和「文件被锁了」——两者的报错长得很像。
4. **最后才考虑**：重启资源管理器 / 注销。重启机器能解决 100% 的句柄问题，但每次都要重启
   说明有人在反复制造它。

## 为什么程序里不做自动杀进程

应用启动时去杀别的进程是越权行为：它不知道那个进程是用户的 VPN、备份还是调试器，杀了会
造成用户完全没预期的影响。工具留在 `scripts/`，由人决定。

唯一自动做的是**单实例**（`tauri-plugin-single-instance`）：第二次启动聚焦已有窗口，而不是
和它抢同一个 WebView2 profile——那是本项目自己能控制的、且唯一一个「多个实例必然冲突」的
场景。

## 排查时容易误判的三种情况

| 现象 | 常见误判 | 实际 |
| --- | --- | --- |
| 删除目录报「拒绝访问」，ACL 看着正常 | 权限坏了 | 目录里有文件被别的进程打开 |
| WebView2 `0x800700AA` | 应用代码 bug | 同一个 profile 被另一个实例/进程占着 |
| 构建成功但 exe 启不来 | 构建坏了 | exe 文件本身被锁（杀毒、VPN、同步盘） |
