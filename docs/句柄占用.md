# 句柄占用：怎么查、怎么破

Windows 上「文件被占用」的报错**从来不会告诉你是谁**：删除目录报「拒绝访问」、写文件报
「另一个进程正在使用」、WebView2 报 `0x800700AA`（资源在使用中）或 `0x8000FFFF`
（灾难性故障）。这些措辞不同，但来源可以完全不同 —— 先分清是哪一类，再动手。

本仓库带了一个工具，不依赖 Sysinternals，不需要管理员权限：

```powershell
node scripts/handles.mjs <路径>                       # 谁占着
node scripts/handles.mjs <路径> --kill                # 杀掉
node scripts/handles.mjs <路径> --kill --only tailscale-ipn   # 只杀某类进程
```

它用的是 **Restart Manager**（Windows 自己那套「文件正在被使用，请关闭以下应用」的机制），
给出的是系统自己的答案，不是启发式猜测。

## 三类问题，三套解法

| 现象 | 句柄查询 | 真因 | 解法 |
| --- | --- | --- | --- |
| 文件被别的进程打开 | **能查到名字** | 进程持有句柄 | 杀掉那个进程 |
| 创建文件被拒（`os error 5`） | 查不到 | **权限/沙箱**：进程被限制在特定目录内 | 换到可写位置 |
| 程序启动即崩、无任何占用 | 查不到 | 上游把 `EACCES` 包装成了别的错误码 | 让程序自己打印真实错误 |

### 第一类：句柄（能查到）

2026-11-15 实测：`tailscale-ipn` 会锁住本仓库 `target\debug\dsh-desktop-app.exe`，
`clash-verge` 会持续锁几十秒。表现是构建成功但启不来，报
「The process cannot access the file because it is being used by another process」。

### 第二类：沙箱写权限（查不到，这是本项目的真凶）

**同样一份二进制，在 `%TEMP%` 能跑，在项目目录里崩** —— 我一度以为是项目路径被针对。
真实原因是 **WebView2 的 profile 目录建不起来**：

```
cannot create C:\Users\Administrator\AppData\Roaming\com.sanjiu2024.dsh-desktop\EBWebView:
拒绝访问。 (os error 5)
```

从 DSH 的沙箱里派生的进程可以写**工作区**和**临时目录**，但写不了 `%APPDATA%` /
`%LOCALAPPDATA%`。WebView2 把这个 `EACCES` 报成了 `0x800700AA`「资源在使用中」或
`0x8000FFFF`「灾难性故障」—— 看上去像占用，其实是权限。

**解法**：把 profile 放到工作区内（本项目现在放在 `<dsh_home>/webview2`）。同一条规则
也适用于任何需要独立数据目录的程序：**数据放在自己被允许写的地方**。

### 第三类：上游吞掉了真实错误（最坑）

上面的真凶之所以查了十几轮，是因为 Tauri 把 `create_dir_all` 的 `EACCES` 包装成了
`ERROR_BUSY`。**判据：`handles.mjs` 说没人占、程序却起不来 → 别再查句柄了**，
去让程序自己把操作系统原话打印出来。

本项目的做法是在 `main.rs` 里显式创建自己的目录并 `eprintln!` 原始错误 —— 一行输出，
省掉十几轮猜测。

## 排查顺序

1. `node scripts/handles.mjs <路径>` —— 有名字就杀掉，结束。
2. 没有名字 → **让程序打印它自己的错误**，不要从状态码反推。
3. 若是「拒绝访问」 → 换到程序有写权限的目录（工作区 / 临时目录）。
4. 最后才考虑重启：能解决 100% 的句柄问题，但每次都要重启说明有人在反复制造它。

## 为什么程序里不做自动杀进程

应用启动时去杀别的进程是越权行为：它不知道那个进程是用户的 VPN、备份还是调试器。工具留在
`scripts/`，由人决定。

唯一自动做的是**单实例**（`tauri-plugin-single-instance`）：第二次启动聚焦已有窗口，而不是
和它抢同一个 WebView2 profile —— 那是本项目自己能控制的、且唯一一个「多个实例必然冲突」的
场景。

## 排查时容易误判的情况

| 现象 | 常见误判 | 实际 |
| --- | --- | --- |
| 删除目录报「拒绝访问」，ACL 看着正常 | 权限坏了 | 目录里有文件被别的进程打开，或当前进程被沙箱限制 |
| WebView2 `0x800700AA` | 被别的实例占着 | 也可能是 profile 目录建不起来（`EACCES`） |
| 构建成功但 exe 启不来 | 构建坏了 | exe 被锁（杀毒、VPN、同步盘），或 exe 所在目录不可执行 |
| 换了安全软件仍然失败 | 安全软件没配好 | 换成别的观察，别重复验证同一个假设 |
