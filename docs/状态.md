## 抓包纠正的四个错误假设

第一版 reducer 是照协议类型猜的，抓了真实事件后发现四处错：

| 猜的 | 实际 |
| --- | --- |
| 用户消息 id 字段是 `messageId` | 是 `id` |
| 一次提问产生一条 `user/message` | **五条** —— 提问 + 四条 `<system-reminder>` 上下文，只能靠 `source.kind` 区分 |
| 流式是 `assistant/chunk` | `assistant/live-chunk`，里面装 `StreamChunk`（`text-delta` 等） |
| 路由在 `data.header.{provider,model}` | 在 `data.header.config.{provider,model}` |

前两条会直接变成可见 bug：重复的用户气泡、一个回答被渲染成几百条消息。

## 协议限制：SDK 没有流式（已由桥插件补上）

`assistant/live-chunk` 是 Web 客户端专用事件，由独立的 follow 连接产生。SDK server 只转发
durable 的 `session/event`（`packages/sdk/server/src/server.ts:164`），而 `assistant/chunk`
在 v4 格式里已经退役。

**后果**：一次提问要等整轮结束才收到 `assistant/message`，中间没有任何增量。

三条出路，**选了第 2 条并已落地** —— `bridge/` 插件，profile patch 挂载，不改内核源码：

插件订阅全局 `agent/assistant-stream`，把每帧写到带标记的 stderr 行；Rust 侧解析成
`dsh-desktop/live-chunk` 通知，走与 stdout 帧同一条广播。**必须装在 `$DSH_HOME/node_modules`**
（Node 从 profile 目录向上解析），装在 `kernel/node_modules` 无效。

> 文件被占用（构建后 exe 启不来、WebView2 报 0x800700AA）见
> [句柄占用](句柄占用.md)：用 `node scripts/handles.mjs <路径>` 定位占用者。
