## 能用

以下三条都是**实际跑出来的**，不是「应该可以」：

| 能力 | 验证方式 | 结果 |
| --- | --- | --- |
| 拉取钉死版本的内核 | `pnpm kernel:fetch` | `@deepseek-ai/dsh 0.2.2-rc.3` 落到 `kernel/`，入口 `kernel/node_modules/@deepseek-ai/dsh/lib/bin.js` |
| 内核 `sdk` profile 可启动 | `node kernel/.../lib/bin.js --profile sdk --help` | 输出 SDK 用法帮助，退出码 0 |
| **JSON-RPC 握手通了** | `pnpm kernel:smoke` | `serverInfo: {"name":"deepseek-harness-sdk-runtime","version":"0.0.1"}` |
| Rust 工作区编译 | `cargo check --workspace` | `EXIT=0`，17 条 warning（全是未使用的依赖占位） |
| 前端类型检查 | `pnpm --filter @dsh-desktop/app check` | 无输出（通过） |
| 依赖安装 | `pnpm install` | 246 包，需 `pnpm approve-builds` 放行 esbuild |

## 不能用

**全部 UI。** 前端只有一屏占位文字，Rust 侧只有 `app_info` 一个命令。
内核能握手，但还不能发消息 —— 桥的进程管理与事件分发是 M0 的下一步。

## 已知问题

| 问题 | 实测数据 | 计划 |
| --- | --- | --- |
| **内核安装 819 MB** | `du -sh kernel` = 819M；`@deepseek-ai/dsh` 有 **91 个直接依赖**，是覆盖全部 profile 的元包 | M6 打包时按 profile 剪枝。已知大件：libreoffice-kit-win32 191M、libreoffice-kit-wasm 146M、client-ui-* 24M、web-frontend 21M、sherpa-onnx 23M、sharp 19M。剪枝前必须先关掉引用它们的 profile 行，否则启动即报缺包 |
| 内核会话日志默认 zstd 压缩 | 未实测（尚未读盘） | profile patch 已设 `compression: 'none'`，M3 验证 |
| 无「列会话」SDK 方法 | 协议只有 9 个方法，无 list | `crates/dsh-store` 扫盘实现 |
| `initialize` 只能调一次 | 源码 `server.ts:215` 写死实例字段 | 按模型建进程池 |
| pnpm 12 默认拦构建脚本 | `ERR_PNPM_IGNORED_BUILDS: esbuild` | `pnpm-workspace.yaml` 里 `onlyBuiltDependencies: [esbuild]` |
