# 设计

本文记录**跨需求**的架构取舍：为什么这样切、否决了哪些方案、边界在哪。单条需求的边界
写在 `docs/requirements/REQ-*.md`，不在这里重复。

状态：草稿 · 2026-11-15 · 对应 v0.0.1

## 1. 只取内核，重写前端

上游 `deepseek-harness` 自带一份完整 Web GUI：React 前端 82,766 行 TS/TSX，
通过 Typert Remote 协议（34 个 namespace，编译器生成的 TypeScript 契约）与 Host 通信。
Electron 壳 `apps/desktop` 只是把这份前端装进 Chromium。

我们要的是一份更小的东西：**agent 内核照用，界面自己写**。

### 否决：复用官方 Web 前端 + Tauri 外壳

最省力的路，两天能出包。否决理由：它解决不了「界面不是我们的」这个问题——
需求是重写 UI，而不是给它换个壳。

### 否决：复刻 Typert Remote 协议

功能面确实最全（设置、工作区、终端、插件市场全都有）。但代价是：

- 34 个 namespace 的 wire 契约要在 Rust 里重写一遍；
- 契约由 TypeScript 编译器在构建时生成，上游一改就要跟；
- 我们连一个可读的协议规范都没有，只有生成物。

同样的功能，用 Tauri 原生 + 一个窄协议就能做到，成本差一个数量级。

### 采用：SDK stdio 桥

内核提供 `dsh --profile sdk`，把整个 runtime 以 **newline-delimited JSON-RPC 2.0 over
stdio** 暴露给外部进程。协议本体 571 行，9 个客户端方法 + 6 个服务端通知，
上游给了 TypeScript 和 Python 两套参考实现。

这是官方为「另一个进程驱动内核」设计的接口，形态正好是我们要的：Rust 主进程是父进程，
内核是子进程，一条管道。

## 2. 三个已知缺口，以及为什么补法比补协议便宜

SDK 面只覆盖「对话」这件事。三个缺口在源码里核实过：

| 缺口 | 上游行为 | 我们的补法 |
| --- | --- | --- |
| 列历史会话 | 无此方法；`session/resume` 只恢复、**不重放历史事件** | 直读 `$DSH_HOME/sessions` 的 JSONL（`crates/dsh-store`） |
| 同一 runtime 换模型 | `initialize` 把 provider/model 钉死在实例字段上 | **每个模型一个 runtime 子进程**（`crates/dsh-runtime` 的池） |
| 设置 / 凭证 / 插件市场 | 走 Remote 面的 controller | 自己写，密钥经环境变量注入子进程 |

三条都是从「内核 / 客户端职责划分」自然长出来的，不是妥协。

### 会话日志：默认压缩，所以要么关压缩要么解压

`sessions/<group>/<id>/session.v4.jsonl.zstd`，默认 `compression: 'zstd'`。
上游明说压缩格式必须经它自己的 backend 读。我们只读不写，所以两条路：

- **A（当前选择）**：profile patch 把 `compression` 设成 `none`，Rust 直接读 NDJSON。
  代价是磁盘 3~5 倍。个人客户端可接受，省掉一个解码路径。
- B：`zstd` crate 流式解帧再按 `\n` 切。等 A 的磁盘占用成为真实问题时再换。

只读意味着**不需要复刻 v0→v4 的迁移链**：读到 `version != 4` 就标记「旧格式，不可读」，
不尝试翻译。

## 3. 模块边界

```
apps/desktop (React) ──invoke/listen──> apps/desktop/src-tauri (组装)
                                              │
                     ┌────────────────────────┼────────────────────────┐
                dsh-runtime              dsh-store               dsh-native
                     │                        │                        │
                  stdio                   磁盘 JSONL              pty / fs
                     │                        │                        │
                     └──────────── dsh 内核（Node，原样）─────────────┘
```

三条硬边界：

1. **`src-tauri` 只组装**。命令函数超过十行就说明逻辑该下沉到 crate。
2. **`dsh-store` 不依赖 `dsh-runtime`**。历史读取必须能脱离内核单独测。
3. **前端不碰 IO 路径**。所有文件系统访问经 `src/lib/ipc.ts`（tauri-specta 生成的绑定）。

`dsh-native` 有意做成独立 crate —— 它和 dsh 没有任何关系，将来可以整体搬走。

## 4. 为什么不多拆 frontend package

前端只有 `apps/desktop` 一个消费者。拆成 npm workspace 包的唯一收益是「将来可能复用」，
而成本是每次改代码都要跨包构建、路径别名、类型引用跳转。等真的出现第二个消费者再拆。

## 5. 类型不手抄

Rust 命令用 `tauri-specta` 生成 TypeScript 绑定。改一个 Rust 结构体，前端立刻类型报错——
这比手写两份接口然后靠人记得同步可靠得多。
