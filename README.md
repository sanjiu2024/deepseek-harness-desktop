# DeepSeek Harness Desktop

A lightweight, cross-platform desktop client for the [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) agent kernel.

We keep **only the kernel** — the agent loop, LLM adapters, tool execution and session persistence — and replace the shipped web front end with our own React UI. The shell is [Tauri 2](https://tauri.app), so the binary is a fraction of the Electron build it replaces.

> Status: **M0a done**. The kernel fetches, boots in its `sdk` profile, and answers a real
> JSON-RPC handshake (`pnpm kernel:smoke`). No UI yet. See [docs/状态.md](docs/状态.md).

## What this is

```
┌──────────────────────────────────────────────┐
│  React 19 + shadcn/ui + Tailwind 4           │  our UI
│  sessions · message stream · tool cards      │
│  approvals · settings · file tree · terminal │
└───────────────────┬──────────────────────────┘
                    │ invoke() / listen()  (generated by tauri-specta)
┌───────────────────┴──────────────────────────┐
│  Rust core (Tauri 2)                         │
│  process pool · NDJSON bridge · session store │
│  pty · fs watch · tray · updater             │
└───────────────────┬──────────────────────────┘
                    │ stdio, JSON-RPC 2.0 / NDJSON
┌───────────────────┴──────────────────────────┐
│  dsh kernel — `dsh --profile sdk`            │  upstream, unmodified
│  agent loop · tools · JSONL persistence      │
└──────────────────────────────────────────────┘
```

The bridge is the kernel's **SDK surface**: newline-delimited JSON-RPC over stdio. It is the interface upstream ships for driving a runtime from another process, and it has two reference implementations (TypeScript and Python) we can read against.

We deliberately do **not** speak the web GUI's Remote protocol — that is a compiler-generated TypeScript contract spanning 34 namespaces, and re-implementing it in Rust would cost more than everything else here combined.

## Layout

| Path | What lives there |
| --- | --- |
| `apps/desktop` | The one application: React front end + Tauri Rust entry point |
| `crates/dsh-runtime` | Kernel process pool, NDJSON framing, request/response correlation |
| `crates/dsh-store` | Read-only access to `$DSH_HOME/sessions` (headers, bodies, index) |
| `crates/dsh-native` | PTY, workspace tree walking, filesystem watch |
| `profiles/sdk` | Kernel profile patches (compression, tools, home directory) |
| `scripts` | Setup and kernel fetch |
| `docs` | Design, engineering, status, requirements |

Deep rule: **`src-tauri` holds no business logic** — it only assembles the crates and commands. **`dsh-store` never depends on `dsh-runtime`.** The front end never touches a filesystem path directly; everything goes through generated bindings.

## Getting started

```bash
# 1. toolchain (rust 1.100, node 24, pnpm 12)
rustup show
node --version
pnpm --version

# 2. dependencies
pnpm install

# 3. the kernel runtime (pinned dsh version, fetched into kernel/)
pnpm kernel:fetch

# 4. prove the wire works before touching UI
pnpm kernel:smoke

# 5. run
pnpm tauri dev
```

You need a DeepSeek API key to actually talk to a model. The client injects it into the kernel
process as `DEEPSEEK_API_KEY`; it is stored in the app's own settings store, never in this
repository.

## Size, honestly

The kernel install is **819 MB** untrimmed — `@deepseek-ai/dsh` is a meta-package with 91 direct
dependencies that carries every profile's packages (LibreOffice kit 337 MB, the official web
frontend, all the client UI packages) whether or not the `sdk` profile loads them.

Trimming is a build-time task tracked in [docs/状态.md](docs/状态.md). Pruning has to happen in
this order — disable the profile rows that reference a package, verify the kernel still boots,
*then* delete the directory. Doing it backwards yields a kernel that dies on startup.

## Kernel compatibility

The kernel is fetched, not vendored. `scripts/fetch-kernel.mjs` pins an exact `@deepseek-ai/dsh` version in `profiles/sdk/kernel.json` and verifies it before use — so a kernel upgrade is a one-line diff with a visible checksum, not a silent drift.

Upstream requires Node ≥ 24.9. The packaged application ships a Node runtime alongside the app; the repository does not.
